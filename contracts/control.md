# 控制通道设计

关联：CON-01…08、OPS-08、CLT-06。状态：语义约束；wire 待实现设计确定。

## 握手与会话

1. Mod 在真实游戏 TCP 端口区分普通 Minecraft 协议与控制协议，前置识别只负责路由。
2. 控制路径通过成熟加密层验证服务端身份，再认证调用者；日志中的认证材料脱敏。
3. 协商协议版本与大小/并发限制；版本协商通过后开放操作，版本冲突明确拒绝。
4. 返回 server instance、run、连接身份、目标类型、实际能力和权限。
5. 网络层验证 frame/请求结构，在有界队列中转入正确的游戏执行线程。

旧实现的同端口 TLS/pin/认证为设计依据。具体识别方式、TLS 配置、认证材料格式和轮换机制在实现 ADR 固定。

## 身份边界

| 身份 | 用途 | 生命周期 |
| --- | --- | --- |
| instance | 识别游戏/世界实例，防止连错目标 | 应能跨同实例重启；世界更换如何判定需明确 |
| run | 识别本次游戏运行 | 每次游戏运行更新 |
| session / principal | 路由连接、认证授权 | 连接、凭证与玩家 UUID 分别定义 |
| request | 关联请求、执行与未知写查询 | 受去重账本和保留期约束 |
| source event / stream | 源端事件顺序与去重 | 与 run、流重置关联 |
| daemon stream | 本地消费/缓存游标 | daemon 启动或显式重置更新 |

各类身份分别表达生命周期与用途。玩家 UUID 标识观察对象，认证 principal 决定访问权限。

## 本地 IPC 与客户端接入

Go CLI 到 daemon 的本地 IPC 要有访问边界、握手版本和明确目标选择，Windows/Unix 具体形式待定。Mod 本地 adapter 要覆盖未发布 LAN 的单机和客户端能力，保持同一业务契约，通过本地入口访问。

daemon 使用明确的实例身份，状态目录按实际配置与实例隔离。

## 连接生命周期

连接状态建议区分 disconnected/connecting/authenticating/ready/reconnecting/stopping；能力以当前连接目标为准，目标变更时缓存按实例/run 失效。

网络中断时，正在执行的写、长拍摄任务、持有者状态和事件 gap 各自处理。重连恢复通信，游戏保持原状态；未知写经状态查询处理。

## 资源边界

必须限定握手耗时、消息长度、连接数、待处理数、每会话队列、反馈长度和下载分段。控制请求饱和时明确拒绝或背压；网络发送在独立线程与有界队列中执行。数值以实测预算固定。
