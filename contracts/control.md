# 控制通道设计

关联：CON-01…08、OPS-08、CLT-06。状态：语义约束；具体 wire 不在本稿定版。

## 握手与会话

1. Mod 在真实游戏 TCP 端口区分普通 Minecraft 协议与控制协议，前置识别只负责路由。
2. 控制路径通过成熟加密层验证服务端身份，再认证调用者；认证材料不进入普通日志。
3. 协商协议版本与大小/并发限制；不支持的版本明确拒绝，不能先执行后解释版本。
4. 返回 server instance、run、连接身份、目标类型、实际能力和权限。
5. 网络层验证 frame/请求结构，在有界队列中转入正确的游戏执行线程。

旧实现的同端口 TLS/pin/认证为设计依据。具体识别方式、TLS 配置、认证材料格式和轮换机制在实现 ADR 固定。

## 身份边界

| 身份 | 用途 | 生命周期 |
| --- | --- | --- |
| instance | 识别游戏/世界实例，防止连错目标 | 应能跨同实例重启；世界更换如何判定需明确 |
| run | 识别本次游戏运行 | 每次游戏运行更新 |
| session / principal | 路由连接、认证授权 | 连接与凭证分别定义，不等于玩家 UUID |
| request | 关联请求、执行与未知写查询 | 受去重账本和保留期约束 |
| source event / stream | 源端事件顺序与去重 | 与 run、流重置关联 |
| daemon stream | 本地消费/缓存游标 | daemon 启动或显式重置更新 |

身份格式可以不同，但用途不能折叠。玩家 UUID 和上下文只表达被观察对象，不授予管理员权限。

## 本地 IPC 与客户端接入

Go CLI 到 daemon 的本地 IPC 要有访问边界、握手版本和明确目标选择，Windows/Unix 具体形式待定。Mod 本地 adapter 要覆盖未发布 LAN 的单机和客户端能力，保持同一业务契约，不要求强制开放网络。

daemon 不用同名文件路径推断是同一游戏实例。状态目录必须按实际配置/实例隔离，不能沿用启动器版本目录导致串实例。

## 连接生命周期

连接状态建议区分 disconnected/connecting/authenticating/ready/reconnecting/stopping；能力以当前连接目标为准，目标变更后旧缓存不能直接作为新状态。

网络中断时，正在执行的写、长拍摄任务、持有者状态和事件 gap 各自处理。重新建立连接只恢复通信，不重建玩家、不清理世界、不自动重发写。

## 资源边界

必须限定握手耗时、消息长度、连接数、待处理数、每会话队列、反馈长度和下载分段。控制请求饱和时明确拒绝或背压；禁止在游戏线程等待慢网络客户端。数值以实测预算固定。
