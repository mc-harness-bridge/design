# 事件、Watch 与时钟契约

关联：EVT-01…07、OPS-07、HOK-01…03。状态：语义约束；容量和枚举待定。

## 两层序列

源端 event ID/sequence 标记游戏事实；daemon 的本地 sequence 用于本地消费。不同 daemon 可以有不同消费游标，但同一源事件必须可关联。源端与 daemon 重启分别产生流边界。

游标至少携带流身份和最后已消费位置。分页返回扫描进度，不能只用“最后一个匹配事件”导致过滤空页永远不前进。历史转实时应避免订阅竞态，可使用先订阅再重放并去重等已验证策略；实现方案通过 fixture 确定。

## 丢失与背压

保留窗口之外、源端缺口、本地缓存覆盖、订阅队列丢失和 webhook 投递失败分别报告。知道具体 sequence 区间时给区间；不知道时说明不确定范围，不伪造精确 dropped 数。

过滤掉事件不是传输损失。daemon 重启 reset 不等于没有事件。队列边界不能用全局无限缓冲掩盖。更强持久化只在实际需求证明必要后引入。

## 时钟矩阵

| 时间 | 含义 | 用途与限制 |
| --- | --- | --- |
| server loop tick | 服务端循环/回调计数 | 冻结时可能仍前进，不自动证明世界模拟推进 |
| dimension game time | 维度游戏时间 | 指定维度；用于相应模拟时序，不等于墙钟 |
| wall-clock timestamp | 实际日期时间 | 跨网络记录、签名时间窗；会受系统时钟影响 |
| monotonic duration | 本地耗时 | 超时与延迟；不能直接跨进程比较绝对值 |
| capture phase | 游戏内采样阶段 | 同 tick 不同阶段可能得到不同状态 |

wait 输入和返回必须写明等待哪种计数。command feedback 的墙钟收集窗口不能宣传为“执行后 N 个模拟 tick”。时钟不可用返回不可用，不用另一个时间填同一字段。

## Watch 使用边界

订阅游戏 callback 事件与按频率采样当前状态分别描述。采样可能遗漏短暂事件；客户端插值采样可能不等于服务端物理。身份链、爆炸中心等候选原语需要实际 callback 和独立验证，不靠最终实体状态重建因果。
