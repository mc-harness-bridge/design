# 事件、Watch 与时钟契约

关联：EVT-01…07、OPS-07、HOK-01…03。状态：语义约束；容量和枚举待定。

## 两层序列

源端 event ID/sequence 标记游戏事实；daemon 的本地 sequence 用于本地消费。不同 daemon 可以有不同消费游标，但同一源事件必须可关联。源端与 daemon 重启分别产生流边界。

游标至少携带流身份和最后已消费位置。分页游标返回实际扫描进度，空过滤页也推进游标。历史转实时应避免订阅竞态，可使用先订阅再重放并去重等已验证策略；实现方案通过 fixture 确定。

## 丢失与背压

保留窗口之外、源端缺口、本地缓存覆盖、订阅队列丢失和 webhook 投递失败分别报告。缺口已定位时报告 sequence 区间；边界未知时返回 unknown range。

过滤、reset 和 gap 分别表示筛选、流重置和传输丢失。队列采用明确容量，持久化按实际消费需求扩展。

## 时钟矩阵

| 时间 | 含义 | 用途与限制 |
| --- | --- | --- |
| server loop tick | 服务端循环/回调计数 | 记录循环进度，冻结时可能仍前进 |
| dimension game time | 维度游戏时间 | 记录指定维度的模拟时序 |
| wall-clock timestamp | 实际日期时间 | 跨网络记录、签名时间窗；会受系统时钟影响 |
| monotonic duration | 本地耗时 | 记录同一进程内的超时与延迟 |
| capture phase | 游戏内采样阶段 | 同 tick 不同阶段可能得到不同状态 |

wait 输入和返回必须写明等待哪种计数。command feedback 窗口按墙钟计时，模拟进度按 game time 记录。时钟缺失返回 unavailable。

## Watch 使用边界

订阅游戏 callback 事件与按频率采样当前状态分别描述。采样可能遗漏短暂事件；客户端插值与服务端物理分别标明来源。身份链、爆炸中心等候选原语需要实际 callback 和独立验证，记录源端触发链。
