# 世界快照与产物设计

关联：SNP-01…09、CTX-06、OPS-05…06。状态：产品目标已确认；capture hook、覆盖表和传输细节待源码审查及 spike。

## 拍摄与消费的分界

Mod 获取游戏内部数据，在一致性要求下执行必要协调并封存产物。Go 传回状态和产物。Agent 在自己的目录中检查、编辑、加载或重建世界，启动独立服务端并开展实验。

manifest 保存源服捕获事实。Agent 在自己的实验记录中关联 artifact ID、研究目的、统计结论与恢复方法。

## 候选 manifest

| 信息组 | 内容 | 作用 |
| --- | --- | --- |
| 身份与版本 | artifact ID、source instance/run、游戏/Mod/数据格式版本 | 防止目标串线和格式误用 |
| 范围 | 维度、区域/集合、loaded/ticking 条件与实际捕获边界 | 防止局部数据冒充全世界 |
| 时点 | 游戏时钟、capture phase、起止时点、进入/离开冻结状态 | 声明一致性和实际源服影响 |
| 覆盖 | 文件类型、额外内存态、未捕获状态和支持级别 | 让消费方判断数据是否满足任务 |
| 文件清单 | 相对路径、长度、hash、总量 | 完整性与安全下载 |
| 状态与限制 | ready/failed、截断/缺失、保留期、失败事实 | 明确半成品和可下载期限 |

字段名与 hash 算法在正式格式决策中固定；manifest 自身的完整性也要保护。产物包含可下载文件和 manifest。

## capture → seal → fetch

1. 验证权限、范围、资源预算与冲突；记录进入时状态。
2. 在明确游戏执行时点捕获声明数据；如有保存/维护动作，记录实际影响。
3. 生成文件 manifest 并完成封存，源端状态切换到 ready。
4. Go 查询 ready 产物，按受限路径/分段获取到临时目录。
5. 验证 manifest、长度和 hash 后，公布本地完成目录；失败保留可诊断状态。
6. 产物按明确期限清理；封存后文件内容固定，重复读取同一产物。

本地公布可采用同文件系统目录 rename 等成熟机制，跨盘行为必须另定义。断点续传的 offset 绑定同一 artifact ID。

## 覆盖审计表必须回答

世界文件、chunk/block entity、实体 NBT/order/passenger、玩家数据、规则、计划 block/fluid ticks、block events、移动活塞、RNG、loaded/ticking 条件、可选 Mod 状态和跨 tick 内存态各自：是否捕获、来自哪里、时点是什么、如何验证、未捕获内容如何标记。

源码审查确定候选捕获方式，实际加载与运行验证恢复结果。保存文件中的 planned ticks 等状态按游戏版本逐项审计。

## 源服后置状态

成功、失败、取消、断线、满盘和过期都记录源服实际状态。拍摄前已冻结应保持冻结；拍摄前运行应按声明策略恢复。恢复结果记录实际执行步骤和剩余状态。

捕获保持源服原区块加载与驻留状态；测量保存同步成本和 tick 延迟。

## 验收范围

文件完整、捕获状态一致、世界可启动、基线行为和运行态续演分别验收，记录具体游戏版本、模组与覆盖范围。
