# 客户端能力与本地访问

Owner：mod 的 client adapter + cli。目标 MUST；新接入形式 TBD。

| ID | 行为与限制 | 验收 |
| --- | --- | --- |
| CLT-01 | 承接客户端 screen/GUI 状态查询，并声明 client vantage、采样时点与可见范围。截图若支持，单独声明格式、来源和能力。 | 有 GUI、无 GUI、客户端未连世界；服务器端不伪造 GUI，未支持截图不宣传已有截图。 |
| CLT-02 | 承接以实际客户端身份发送 chat；与服务端命令回复/广播分开，不冒充另一个玩家。 | 实际 sender 与目标世界可核对；只服务端目标返回不支持，不能偷用管理员 say 冒充 client chat。 |
| CLT-03 | 承接客户端 connect、world 打开与 LAN 发布原语，明确是会改变客户端会话的操作。 | 加入服务端、打开指定存档、发布并读取实际 LAN 端口；取消/失败和世界切换更新身份。 |
| CLT-04 | 承接 record_start/record_stop 的每 tick 客户端采样，格式、容量、产物、停止/断线语义明确；不当作服务端精确物理数据。 | 启动/停止、重复启动、容量边界、客户端退出；捕获来源可识别，并可取得声明产物。 |
| CLT-05 | 每种 client-only 能力单独在 schema/capability 呈现；当前可用性与目标类型分开，不以旧 adapter 删除为理由隐去功能。 | 专用服、整合服、菜单和客户端无世界四种状态；错误 vantage 明确拒绝。 |
| CLT-06 | 未发布 LAN 的本机单机提供显式本地访问路径，仍保留 server 权威查询和 client-only 区分；不要求玩家为观察退出或开放网络。 | 真实未发布 LAN 的世界上读取玩家现场、事件和支持操作；不偷偷发布 LAN 或转旧 Python transport。 |

## 生命周期边界

connect/world/lan 是已确认的客户端游戏原语；Agent 启动服务端进程、复制实验世界和部署实验实例是外部终端职责。不要把这两类能力合成产品内实验管理器。

GUI 查询承接旧 screen 能力；像素截图作为独立视觉接口定义需求和验收。
