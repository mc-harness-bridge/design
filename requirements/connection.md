# 连接、身份与多会话

Owner：mod + cli。状态：部署目标 MUST；本地适配器与 wire 方案 TBD。

| ID | 行为与限制 | 验收 |
| --- | --- | --- |
| CON-01 | 专用服和已发布 LAN 的整合服由 Mod 在实际游戏监听端口接入控制连接；普通玩家连接照常。源服无需 Go daemon、SSH、外部分流代理或第二公网控制端口。 | 实际专用服和 LAN 上玩家与控制并存；正常协议未被误识别，坏帧只影响控制连接。 |
| CON-02 | 使用成熟加密方案验证服务端身份并认证调用者；支持凭证配置、撤销/轮换与服务端权限，不把协议识别字节当作密钥。 | 正确身份通过；错误 pin/身份、错误凭证、撤销、权限不足、协议不匹配被明确拒绝。 |
| CON-03 | 控制会话身份独立于玩家，连接不创建玩家实体、假人或玩家驻留条件。 | 零玩家服务器可连接；连接/断线前后玩家列表不变，加载与身体策略无隐含动作。 |
| CON-04 | 多 daemon 直接连接 Mod，各有响应路由、权限和事件消费；没有全局唯一 daemon 网关。 | 两个独立进程并发查询和受控写；请求/响应不串线，不能借用别人的授权。 |
| CON-05 | 稳定实例身份与每次运行身份分开；目标选择显式，游戏重启、世界切换、daemon 重启可诊断。 | 同世界重启 run 变化；切换目标/世界不会沿用错误缓存或请求账本；不静默连到别的世界。 |
| CON-06 | CLI 短调用与 daemon 长连接独立于 harness 生命周期；重连有界退避和状态，不能自动重放非幂等写。 | harness/CLI 退出不停止游戏连接；游戏重启恢复后有新身份；unknown 写仍可追踪。 |
| CON-07 | 网络线程与游戏线程分离；握手、帧大小、连接数、待处理请求、队列和超时有界。慢客户端不无限阻塞游戏或其他会话。 | 畸形帧、超大消息、停读连接、满队列与并发压力；记录 tick 和正常会话响应影响。 |
| CON-08 | daemon 本地调用入口具备明确访问边界、实例锁/并发启动保护、版本检查、健康检查和优雅停止；不把本地 IPC 默认开放成公网 API。 | 两次启动、陈旧锁/状态、错误版本、非预期本地调用者、终止信号及清理失败可诊断。 |

## 部署限制

LAN 返回实际端口；未发布 LAN 的单机走 CLT-06。不同目录、机器和网络环境必须记录实测范围。同机不同文件根或 WSL 不等于第二物理主机证据。

自动发现可提供建议，不能在失败时悄悄改 transport、vantage、凭证或目标。代理兼容按独立矩阵验证。
