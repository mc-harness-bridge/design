# 玩家现场与权威观测

Owner：mod；cli 忠实呈现。状态：MUST，数据范围与资源预算待实现确定。

## 需求

| ID | 行为与限制 | 验收 |
| --- | --- | --- |
| CTX-01 | 按稳定 UUID 查询指定玩家；名称可作便利输入，返回解析到的 UUID、维度、位置、朝向、游戏模式及实际可得状态。查询显式选择目标玩家。 | 两个玩家在不同维度同时查询；名称变化、离线、未知或歧义得到结构化结果，无串人。 |
| CTX-02 | 从服务端玩家眼位与朝向做视线查询，区分 block/entity/miss/unavailable，声明距离和碰撞/目标规则；命中结果标明服务端来源。 | 方块、实体、遮挡、无碰撞可选目标、未命中和离线场景；位置/朝向与同次采样一致。 |
| CTX-03 | 在服务端收到玩家聊天时捕获紧凑现场；关联 sender UUID、事件身份、context_id、时钟、维度、位置、朝向和视线结果。事件引用紧凑现场 bundle。 | 玩家发言后移动/传送，延迟取回仍是接收时现场；多人交错消息正确关联。 |
| CTX-04 | context_id 是 opaque 引用，有界缓存、明确过期和容量逐出；过期引用返回 expired 状态。捕获失败或 fallback 有标签。 | TTL 到期、容量逐出、Mod 重启、丢失 receipt、无法捕获 sender 等场景；缓存上限可验证。 |
| CTX-05 | 全局 server/world 状态与指定玩家现场分别提供；无玩家专用服仍可查询支持的权威数据。维度输入明确，返回实际源与范围。 | 零在线玩家、多个维度、非法/未知维度、整合服和专用服；错误使用结构化错误结果。 |
| CTX-06 | 承接受支持非玩家实体的 NBT、UUID、类型、维度、tick 顺序和 passenger/vehicle/root 关系；明确玩家排除、未 tick/未加载覆盖及截断。 | 与游戏侧独立观测比对实体集合、顺序和骑乘关系；查询和实体导出一致；orderHash 校验集合顺序，行为通过独立观测验收。 |

## 非侵入要求

现场查询保持玩家位置、相机、实体和区块加载状态；访问权限由服务端根据认证会话裁决。

客户端画面和 GUI 在 CLT 模块保留，明确为 client vantage。服务端视线报告游戏侧现场，客户端画面报告渲染侧现场。

## 设计接口

具体操作名与 JSON schema 尚未固定；历史 player/context/state/entities 用于承接索引。每种数据附取样来源和时点，context 与 live query 使用不同的语义入口。
