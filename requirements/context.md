# 玩家现场与权威观测

Owner：mod；cli 忠实呈现。状态：MUST，数据范围与资源预算待实现确定。

## 需求

| ID | 行为与限制 | 验收 |
| --- | --- | --- |
| CTX-01 | 按稳定 UUID 查询指定玩家；名称可作便利输入，返回解析到的 UUID、维度、位置、朝向、游戏模式及实际可得状态。不得默认第一个在线玩家。 | 两个玩家在不同维度同时查询；名称变化、离线、未知或歧义得到结构化结果，无串人。 |
| CTX-02 | 从服务端玩家眼位与朝向做视线查询，区分 block/entity/miss/unavailable，声明距离和碰撞/目标规则；不读取客户端 crosshair 充当权威命中。 | 方块、实体、遮挡、无碰撞可选目标、未命中和离线场景；位置/朝向与同次采样一致。 |
| CTX-03 | 在服务端收到玩家聊天时捕获紧凑现场；关联 sender UUID、事件身份、context_id、时钟、维度、位置、朝向和视线结果。不要每条聊天附整个世界。 | 玩家发言后移动/传送，延迟取回仍是接收时现场；多人交错消息正确关联。 |
| CTX-04 | context_id 是不透明引用，有界缓存、明确过期和容量逐出；读取过期引用不能退化成另一个玩家或实时现场。捕获失败或 fallback 有标签。 | TTL 到期、容量逐出、Mod 重启、丢失 receipt、无法捕获 sender 等场景；缓存上限可验证。 |
| CTX-05 | 全局 server/world 状态与指定玩家现场分别提供；无玩家专用服仍可查询支持的权威数据。维度输入明确，返回实际源与范围。 | 零在线玩家、多个维度、非法/未知维度、整合服和专用服；错误不进入成功信封。 |
| CTX-06 | 承接受支持非玩家实体的 NBT、UUID、类型、维度、tick 顺序和 passenger/vehicle/root 关系；明确玩家排除、未 tick/未加载覆盖及截断。 | 与游戏侧独立观测比对实体集合、顺序和骑乘关系；查询和实体导出一致；不把 orderHash 当作行为证明。 |

## 非侵入要求

读取现场不移动玩家、不生成假人、不改变相机、不强制加载范围外区块。服务器权限裁决仍适用：知道 sender 的 UUID 不等于有权读取任意玩家数据。

客户端画面和 GUI 在 CLT 模块保留，明确为 client vantage。服务端视线是服务端已知现场，不承诺与客户端渲染帧的像素完全一致。

## 设计接口

具体操作名与 JSON schema 尚未固定；历史 player/context/state/entities 是承接索引，不要求维持旧拼写。每种数据附取样来源和时点，context 与 live query 使用不同的语义入口。
