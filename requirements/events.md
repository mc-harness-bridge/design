# Watch、事件与时钟

Owner：mod 事件与时点；cli 消费与缓存。EVT-01…06 为 MUST；EVT-07 为 DISCUSSION。

| ID | 行为与限制 | 验收 |
| --- | --- | --- |
| EVT-01 | 事件有源实例/运行、源流身份、顺序、类型、时点和必要上下文。Go 若生成消费流编号，与源事件身份分开。 | 两连接收到同一源事件可关联；游戏/daemon 重启后 ID 不误碰撞，缺少源信息不能被编造。 |
| EVT-02 | 支持游标读取、分页、过滤与持续跟随；明确 since 是何种边界，分页游标不因过滤而卡死。 | 多页重放、边界重复、空过滤页、历史转实时竞态、目标过滤和取消；无未报告漏段。 |
| EVT-03 | 缓存有界，过期游标、队列溢出、重启和无法回放均有机器可读 gap/reset/truncation。没有事件与事件已丢失不同。 | 故意落后、缩小容量、停读、断线和重启；丢失边界能被消费者识别。 |
| EVT-04 | Watch 慢消费者和 webhook 故障不能阻塞游戏连接读取或正常请求。内存、队列、重试和保留数值有实际预算。 | 慢接收方和高速事件共同运行；验证其他调用、游戏 tick 与可见丢失信号。 |
| EVT-05 | 区分 server loop tick、每维度 game time、墙钟时间和本地等待耗时；采样相位和时钟来源明确。 | 运行、tick freeze、tick step、跨维度和时间调整；计数增加不被报告成模拟必然推进。 |
| EVT-06 | wait/采样报告其等待的计数和实际观测区间；取消、冻结、超时、运行身份变化明确，不保证未声明的 tick 精确动作。 | wait 完成但模拟未推进、反馈窗口跨 tick、游戏重启、超时与取消；标签和返回值一致。 |
| EVT-07 | 保留瞬时事件研究需求：真实实体身份链、爆炸中心、首次接触、速度写入来源、UUID 与采样相位。先确定最小 callback 范围。 | 先形成需求/源码/性能依据；若实现，用独立仪表比对，不能用轮询/FIFO/最终位置猜事件因果。 |

## 非目标与待定

不预先建设通用事件总线、持久消息平台或 exactly-once 系统。持久回放、每订阅者队列与更强背压，只有真实需求和故障证据支持后才增加。去重窗口内一次触发不代表所有故障下恰好一次。

Watch 可以由事件或明确频率的状态采样提供。两者在来源、采样相位、漏掉瞬时变化的可能性和资源成本上必须分别说明。
